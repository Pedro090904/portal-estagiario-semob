1. A Filosofia e o Modelo Mental da Arquitetura

No desenvolvimento front-end moderno, o erro mais frequente de quem está iniciando é colocar todo o código no mesmo arquivo: requisições de API, estados locais do formulário, validações de texto, formatação de datas, JSX e estilos CSS. Quando esse arquivo atinge centenas de linhas, qualquer pequena alteração quebra a tela inteira.

Nossa arquitetura resolve isso através de um princípio basilar: Separação Estrita de Responsabilidades em Camadas Unidirecionais.

1.1 A Separação em 5 Camadas

Camada Papel Arquitetural Responsabilidade Principal
1. Types O Contrato Define as regras e interfaces estruturais dos dados (entidades, DTOs e props de componentes).
2. Services O Mensageiro Executa as requisições HTTP (GET, POST, PUT, DELETE) com os microsserviços do backend.
3. Hooks O Cérebro Gerencia o estado reativo (useState), aciona o Service, orquestra loadings, erros e regras de tela.
4. Smart UI O Maestro A página/container principal. Conecta o Hook aos componentes visuais, controlando layout e permissões.
5. Dumb UI Os Operários Componentes puramente visuais (cards, formulários, modais). Apenas renderizam dados e repassam eventos via props.

1.2 Diagrama de Fluxo Unidirecional de Dados

Os dados fluem sempre em sentido descendente (do backend até a tela), enquanto as intenções do usuário sobem em sentido ascendente (do clique até a mutação no backend):

REGRA DE OURO DO ISOLAMENTO FRONT-END

Nenhum componente visual deve saber como os dados foram obtidos:

  • O componente visual (components/*) nunca importa a biblioteca axios nem sabe qual endpoint foi chamado;
  • O serviço HTTP (services/*) é agnóstico à interface: não utiliza useState, useEffect nem JSX;
  • O Hook customizado (hooks/*) concentra toda a reatividade e regras da tela. Se você mudar o visual amanhã, o hook permanece intacto.

1.3 A Analogia Didática do Restaurante 🍽️

Para fixar na memória como as partes colaboram entre si, compare com o funcionamento de um restaurante de alto padrão:

  • types/ (O Cardápio e as Fichas Técnicas): Define o que existe no restaurante. Ex: "Uma Refeição tem nome (texto), preço (número) e lista de acompanhamentos". Nada vai para o fogo sem receita prévia.
  • services/ (O Fornecedor / Entregador): É o veículo de logística que busca insumos no mercado externo (o servidor backend). Ele não cozinha nada e não sabe quem vai comer; apenas entrega e coleta pacotes íntegros.
  • hooks/ (A Cozinha e o Chef): Onde o prato é preparado. O Chef sabe quando o forno está assando (loading = true), sabe se faltou gás (erro de rede) e organiza os pratos prontos esperando o garçom.
  • components/ (Os Garçons e a Mesa — Dumb Components): Eles não cozinham. Pegam o prato já finalizado e o apresentam com elegância ao cliente. Se o cliente pede a conta (clica num botão), o garçom apenas repassa o aviso à cozinha.
  • Index.tsx (O Gerente do Salão — Smart Component): O maestro que certifica que a cozinha (hook) atenda à mesa certa e distribua os pedidos com harmonia.

2. Estrutura de Pastas e Responsabilidades

2.1 Mapeamento Canônico de uma Feature

Toda nova funcionalidade dentro do ecossistema front-end (ex: Tarefas, Notícias, Veículos) deve habitar um diretório dedicado contendo a seguinte estrutura padronizada:

src/features/ (ou src/modulos/)
└── Tarefas/
    ├── types/
    │   └── tarefa.ts         ← Contratos TypeScript (Entidades, DTOs e Props)
    ├── services/
    │   └── tarefasService.ts ← Camada de comunicação HTTP com o Backend
    ├── hooks/
    │   └── useTarefas.ts     ← Lógica de negócio, loading, validações e estado
    ├── components/
    │   ├── TarefaCard.tsx    ← Dumb Component: card visual de exibição
    │   └── TarefaForm.tsx    ← Dumb Component: formulário de cadastro/edição
    └── TarefasIndex.tsx      ← Smart Component: container principal da tela

2.2 Matriz de Responsabilidades (O Que Fazer vs. O Que NUNCA Fazer)

Pasta / Camada O QUE DEVE SER FEITO AQUI ✅ O QUE NUNCA DEVE SER FEITO AQUI ❌
types/ • Declarar interfaces das entidades do banco/API.
• Declarar DTOs para envio de dados (Create/Update).
• Tipar explicitamente as Props de cada componente visual.		 • NUNCA use o tipo genérico any.
• NUNCA crie funções com lógica executável aqui (apenas declarações de tipos).
services/ • Declarar funções assíncronas que utilizam a instância global do Axios (api.get, api.post).
• Desduplicar requisições em voo (*inflight promise*) se necessário.
• Retornar tipagens estritas em Promises (Promise<T>).		 • NUNCA utilize hooks do React (useState, useEffect).
• NUNCA monte elementos JSX ou manipule o DOM.
• NUNCA exiba alertas (alert()) diretamente aqui.
hooks/ • Armazenar estados locais da tela (useState).
• Acionar os services e manipular flags de carregamento (isLoading).
• Tratar erros, validar regras de negócio e limpar formulários após o sucesso.		 • NUNCA monte código HTML ou retorne tags JSX.
• NUNCA acesse propriedades do DOM nativo sem useRef.
components/ • Renderizar JSX limpo, semântico e estilizado com Tailwind CSS.
• Receber dados e funções exclusivamente por meio de props.
• Disparar callbacks (ex: onClick, onSubmit) repassando eventos ao pai.		 • NUNCA faça chamadas de API diretamente.
• NUNCA importe arquivos da pasta services/.
• NUNCA acesse localStorage ou sessionStorage.
Index.tsx • Invocar o Custom Hook principal da tela.
• Compor a hierarquia visual alimentando os Dumb Components.
• Controlar permissões de acesso e botões de escrita (RBAC).		 • NUNCA declare lógica complexa de formulário diretamente no arquivo da tela (delegue para o Hook).

3. As 4 Regras de Ouro (Anti-patterns e Erros Críticos)

REGRA DE OURO 1: NENHUMA CHAMADA DE API DENTRO DE COMPONENTES VISUAIS

É expressamente proibido fazer axios.get('http://...') ou fetch() diretamente no corpo de um componente visual ou dentro de um onClick. Toda comunicação com a rede pertence exclusivamente à pasta services/.

REGRA DE OURO 2: PROIBIDO O USO DO TIPO "ANY"

Usar any inutiliza o compilador do TypeScript e mascara erros em tempo de desenvolvimento. Se você não sabe a estrutura do dado vindo da API, inspecione a rota no Swagger e crie a interface no types/.

REGRA DE OURO 3: COMPONENTES EM COMPONENTS/ DEVEM SER "BURROS"

Cards, tabelas, inputs e modais devem ser previsíveis: recebem props e produzem visual. Não devem conter regras de sincronização com o banco de dados.

REGRA DE OURO 4: NUNCA DEIXE BLOCOS CATCH EM SILÊNCIO

Nunca capture um erro em bloco try/catch sem apresentar feedback para o usuário e registrar no console. Falhas silenciosas fazem o usuário clicar compulsivamente achando que a aplicação travou.

4.2 Passo 2: Camada de Comunicação HTTP (services/tarefasService.ts)

Crie o arquivo src/features/Tarefas/services/tarefasService.ts:

import api from '../../../services/api'; // Singleton configurado do Axios
import { Tarefa, CreateTarefaDTO } from '../types/tarefa';

const RECURSO_URL = '/tarefas';

export const tarefasService = {
  // Buscar todas as tarefas
  async listar(): Promise<Tarefa[]> {
    const response = await api.get<Tarefa[]>(RECURSO_URL);
    return Array.isArray(response.data) ? response.data : [];
  },

  // Criar nova tarefa
  async criar(dados: CreateTarefaDTO): Promise<Tarefa> {
    const response = await api.post<Tarefa>(RECURSO_URL, dados);
    return response.data;
  },

  // Alternar status de conclusão
  async atualizarStatus(id: number, concluida: boolean): Promise<Tarefa> {
    const response = await api.patch<Tarefa>(`${RECURSO_URL}/${id}`, { concluida });
    return response.data;
  },

  // Excluir tarefa
  async excluir(id: number): Promise<void> {
    await api.delete(`${RECURSO_URL}/${id}`);
  }
};

4.3 Passo 3: O Cérebro da Tela — Custom Hook (hooks/useTarefas.ts)

Crie o arquivo src/features/Tarefas/hooks/useTarefas.ts:

import { useState, useEffect, useCallback } from 'react';
import { tarefasService } from '../services/tarefasService';
import { Tarefa, CreateTarefaDTO } from '../types/tarefa';

export function useTarefas() {
  const [tarefas, setTarefas] = useState<Tarefa[]>([]);
  const [isLoading, setIsLoading] = useState<boolean>(false);
  const [erro, setErro] = useState<string | null>(null);

  // Estados dos campos do formulário
  const [titulo, setTitulo] = useState('');
  const [descricao, setDescricao] = useState('');
  const [prioridade, setPrioridade] = useState<'BAIXA' | 'MEDIA' | 'ALTA'>('MEDIA');

  // 1. Busca inicial
  const carregarTarefas = useCallback(async () => {
    setIsLoading(true);
    setErro(null);
    try {
      const dados = await tarefasService.listar();
      setTarefas(dados);
    } catch (err: any) {
      console.error('Falha ao carregar tarefas:', err);
      setErro('Não foi possível carregar as tarefas. Verifique sua conexão.');
    } finally {
      setIsLoading(false);
    }
  }, []);

  useEffect(() => {
    carregarTarefas();
  }, [carregarTarefas]);

  // 2. Submit do formulário
  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    if (!titulo.trim() || !descricao.trim()) {
      alert('Por favor, preencha o título e a descrição.');
      return;
    }

    setIsLoading(true);
    try {
      const dto: CreateTarefaDTO = {
        titulo: titulo.trim(),
        descricao: descricao.trim(),
        prioridade
      };

      await tarefasService.criar(dto);

      setTitulo('');
      setDescricao('');
      setPrioridade('MEDIA');
      await carregarTarefas();
      alert('Tarefa cadastrada com sucesso!');
    } catch (err: any) {
      alert(`⚠️ ${err?.response?.data?.message || 'Erro ao cadastrar tarefa.'}`);
    } finally {
      setIsLoading(false);
    }
  };

  // 3. Alternar conclusão
  const handleAlternarConcluida = async (id: number) => {
    const item = tarefas.find(t => t.id === id);
    if (!item) return;

    try {
      await tarefasService.atualizarStatus(id, !item.concluida);
      await carregarTarefas();
    } catch (_error) {
      alert('Erro ao atualizar status da tarefa.');
    }
  };

  // 4. Excluir com confirmação
  const handleExcluir = async (id: number) => {
    if (!window.confirm('Tem certeza que deseja remover esta tarefa?')) return;
    try {
      await tarefasService.excluir(id);
      await carregarTarefas();
    } catch (_error) {
      alert('Erro ao excluir tarefa.');
    }
  };

  return {
    tarefas,
    isLoading,
    erro,
    titulo, setTitulo,
    descricao, setDescricao,
    prioridade, setPrioridade,
    handleSubmit,
    handleAlternarConcluida,
    handleExcluir,
    recarregarTarefas: carregarTarefas
  };
}

            <TarefaForm
              titulo={titulo}
              setTitulo={setTitulo}
              descricao={descricao}
              setDescricao={setDescricao}
              prioridade={prioridade}
              setPrioridade={setPrioridade}
              isLoading={isLoading}
              onSubmit={handleSubmit}
            />
          </div>

          {/* Listagem */}
          <div className="lg:col-span-7 space-y-4">
            <div className="flex items-center justify-between px-1">
              <h3 className="text-xs font-black text-slate-400 uppercase tracking-widest">
                Tarefas Cadastradas
              </h3>
              <span className="bg-slate-200 text-slate-700 text-[10px] font-black px-2 py-0.5 rounded-full">
                {tarefas.length}
              </span>
            </div>

            <div className="space-y-3">
              {tarefas.map((tarefa) => (
                <TarefaCard
                  key={tarefa.id}
                  tarefa={tarefa}
                  onExcluir={handleExcluir}
                  onAlternarConcluida={handleAlternarConcluida}
                />
              ))}

              {tarefas.length === 0 && !isLoading && (
                <div className="p-12 text-center bg-white rounded-3xl border-2 border-dashed border-slate-200">
                  <CheckSquare className="w-8 h-8 text-slate-300 mx-auto mb-2" />
                  <p className="text-xs font-bold text-slate-400 uppercase tracking-widest">
                    Nenhuma tarefa pendente
                  </p>
                </div>
              )}
            </div>
          </div>

        </div>

      </div>
    </div>
  );
}

4.6 Passo 6: Registro da Rota e Lazy Loading na Aplicação

Para disponibilizar a nova funcionalidade na aplicação sem sobrecarregar o carregamento inicial, declare-a com lazy:

import { lazy } from 'react';

// 1. Carregamento sob demanda (Code-Splitting)
const TarefasIndex = lazy(() => import('../features/Tarefas/TarefasIndex'));

// 2. Registro no catálogo de rotas
export const routes = [
  {
    path: '/tarefas',
    component: TarefasIndex,
    title: 'Gestão de Tarefas'
  }
];

5. Dicionário Rápido & Guia de Bolso

Conceito Como Fazer do Jeito Certo ✅ O Que Evitar a Todo Custo ❌
Chamadas HTTP Invocar o método do service (ex: tarefasService.listar()). Fazer axios.get() solto dentro de componente ou hook aleatório.
Loading State Desabilitar botões e exibir spinners animados (Loader2 animate-spin). Permitir que o usuário dê múltiplos cliques no botão salvando em duplicidade.
Tipagem Criar interfaces detalhadas e DTOs no diretório types/. Usar any para burlar avisos do compilador TypeScript.
Estilização Utilizar classes utilitárias do Tailwind CSS (bg-slate-50, rounded-2xl). Usar estilos inline style={{ marginTop: 20 }} sem necessidade.
Tratamento de Erros Notificar o usuário de forma amigável e registrar o erro via console.error. Deixar blocos catch {} vazios em silêncio.
Desacoplamento Manter componentes em components/ puros e reativos apenas a props. Acessar localStorage ou invocar regras de negócio no componente visual.
